# Spine 创作工作台

已在创作空间增加 **Spine** 页签。工作台使用天蓝色界面，支持整图上传与生成、纯色背景处理、角色部件生成、带坐标的拆层清单导入、本机 ComfyUI / See-through 拆层任务接入、骨骼与动作会话，以及多图关键姿态、姿态拟合和骨骼轨道插帧。可创建实际骨骼、加权网格和动作曲线，在本机预览与编辑，并导出 Spine 4.2 资产。

本机拆层的协议、恢复流程和界面已实现并通过模拟服务验证，真实 GPU 拆层仍需在用户本机 ComfyUI 环境验收。姿态研究现在可通过支持图片的会话模型估计每个部件的 R/B/X/Y，再审阅并采纳；用户仍可手工修改。“确认目标”补齐缺失部件，“本地姿态微调”按目标图优化所选角度，“插帧”生成可继续编辑的骨骼关键帧；桌面版还可用本地 RIFE 生成 RGB 参考帧，再回到识别、拟合和人工审阅流程。V4 会话可以提出任意对象的拆件草案、逐件生成贴图，以及修改骨骼和动作轨道；单图中的遮挡部位仍依赖生图模型补绘，须人工检查。逐阶段记录见 [第二版实施日志](SPINE_V2_IMPLEMENTATION_LOG.md)、[第三版实施日志](SPINE_V3_IMPLEMENTATION_LOG.md)、[第四版实施日志](SPINE_V4_IMPLEMENTATION_LOG.md) 和 [第五版实施日志](SPINE_V5_IMPLEMENTATION_LOG.md)。

## 使用

1. 从侧栏进入「创作空间 → Spine」。选择「体验机器人示例」可在没有生图连接的情况下体验完整流程。
2. 新建角色，上传或生成一张整图。整图保存完整画布；白色等纯色背景可用“去纯色背景”处理，原图仍可还原。处理只删除与边界相连、颜色接近的区域，不会自动分离肢体。也可直接导入带透明背景的 PNG 部件；JPEG/WebP 部件不会自动去背景。部件图会裁去透明边缘，并把最长边限制到 1024 像素。
3. 或者填写角色描述，选择已有生图连接和模型。可上传最多 3 张参考图，也可直接从最近 24 个完成的生图历史结果中选择。图 1 作为角色身份参考，其余图片补充细节。
4. 「生成 1 张」生成指定部件；「补齐六部件」按缺失的躯干、头、左右臂、左右腿依次调用生图服务，每个部件一次请求。没有手动参考图时，工作台整图作为身份参考。也可把整图送入“本地 AI 拆层”作为拆层输入。生成失败时已完成部件保留。「停止后续生成」会保留当前请求的结果，再停止后续请求；它不撤销已经发给服务商的请求。
5. 切换到「绑定姿势」，拖动部件，设置尺寸、枢轴和父骨骼。部件列表顺序也是绘制顺序，靠后的部件绘制在上面。左右指画面左右。枢轴是从图片左上角计算的 0–1 坐标，骨骼位置使用 Y 向上的坐标系。
6. 为部件指定动作角色，然后生成「呼吸待机」「挥手」或「原地行走」。打开骨骼和网格叠加，拖动时间轴，编辑旋转、弯曲、X/Y 位移、线性或阶梯插值。时长调整会缩放关键帧时间。部件、动作和关键帧修改均支持最近 30 步撤销；一个拖动操作计为一步。
   已有部件后，也可在“骨骼与动作会话”描述改动。模型提出草案，界面校验后由用户确认应用；会话记录随工程保存。
7. 工程自动存入本机应用 WebView 的 IndexedDB，也可手动保存。切换到聊天或其他创作页签时，工作台保持挂载，动画停止占用播放循环，生成任务继续。导出 ZIP 后可备份或迁移到其他机器。
8. 「导出 Spine」生成 ZIP。解压后，在 **Spine 4.2** 使用「导入数据」导入 `skeleton.json`，新建骨架，图片路径使用同目录的 `images/`，然后在编辑器内保存为 `.spine`。导出物不冒充 `.spine` 二进制工程。

生图步骤使用用户已配置的生图服务，可能是远程服务；骨骼编译、预览、图集打包与工程保存均在本机完成。`gpt-image-2` 会请求纯绿背景并在本机尝试边界连通抠图；其他模型优先请求透明背景。抠图只适用于接近纯色的背景，不规则背景会保留供人工修正。实际部件一致性和遮挡补全质量仍须人工检查。

生成贴图不满意时，选择该部件，在右侧填写“单件重绘要求”并点击“重绘当前部件”。比如身体贴图意外带上袖子，可明确要求“只保留无袖衣身和裙摆，删除两侧袖子”。生成结果先进入下述审阅界面，采纳后才替换贴图。

父骨骼和绘制顺序分别控制。拆件草案可为部件指定绘制层级；在会话中也可要求“马尾放到头后、腿放到裙摆后”，审阅并应用方案。继续描述动作修改会更新同名动作，应用后选中该动作，便于直接播放检查。

已有部件后，每次会话会附上原图、当前绑定姿态的装配图、标注枢轴和父子关系的装配图，以及编号分件图。可以直接描述“左肩有缝隙，依据当前装配修正位置和枢轴”等问题。模型能据当前贴图提出几何调整；重复衣领等已画进贴图的内容仍应通过单件重绘修正。装配图是静态绑定姿态，动作效果需要播放检查。

单件重绘同时参考原图、计划中的局部区域和当前贴图。填写右侧「单件重绘要求」后生成候选，在审阅窗口切换「贴图对照」「装配对照」「动作对照」，两边按同一时间播放；可拖到精确末帧检查接缝。点击「采纳重绘贴图」后才保存替换，骨骼和动作保持，仍可撤销。「放弃结果」保留旧贴图，可以修改要求后再生成。候选仅保留在当前审阅中，刷新、切换工程或修改部件后需重新生成。

## 第三版：多图关键姿态、拟合与插帧

1. 先选中一个动作，在时间轴定位到一个姿态，点击「姿态研究」。工作台会为当前动作建立可持久化的姿态研究。
2. 用「记录时间轴姿态」把当前动作采样成关键姿态；或导入 PNG/JPEG/WebP 姿态图。可在「关键姿态时间」指定时间，填写描述后点击「生图关键姿态」。生图自动附上工程整图、目标时间最近的前后姿态图，以及用户选择的参考图，按此顺序约束身份和动作连续性。姿态图保留完整画布与透明留白，并随工程保存。
3. 已有两个不同时间的姿态图时，把时间设在两者之间，点击「生成中间姿态图」。模型据两端图片生成一张新的视觉姿态图；也可以在「本地像素补帧（RIFE）」中一次生成 1、3 或 7 张 RGB 参考图。所有结果仍需点击「AI 识别姿态」并审阅、采纳骨骼目标；图片不会绕过审阅直接写入动作。生成中修改前后参考图或目标时间被占用时，迟到结果会被丢弃。
4. 在姿态卡片中选择要编辑的部件，调整 R（旋转）、B（弯曲）、X/Y 位移。导入和生成时可指定姿态时间；图片本身只是视觉参考，不会自动转换为骨骼目标。
5. 点击单帧「确认目标」确认手工目标。缺失部件会从当前动作同一时刻采样填入，并标记为需要检查；完整部件目标保留用户修改。图像驱动的微调在下述姿态审阅区进行。
6. 至少准备两个不同时间点的姿态，选择 12/24/30 FPS 和线性或阶梯曲线。点击「插帧为新动作」会保留原动作并建立可编辑的新 clip；「覆盖当前动作」会替换当前骨骼轨道。生成后的关键帧可在原时间轴继续调整。
7. 姿态研究和图片会随工程保存。每个工程最多 8 个研究、每项最多 64 张姿态图；图像数据、动作数和关键帧仍受工程总限制约束。

姿态目标插帧使用确定性曲线采样：角度走最短路径，X/Y 线性混合，阶梯模式保持前一姿态直到后一关键姿态。它生成的是 Spine 骨骼时间轨道；RIFE 只提供 RGB 参考图，不生成透明视频，也不会替代骨骼拟合。尚未集成 OpenPose/MediaPipe、ToonCrafter。

姿态卡片的「AI 识别姿态」打开审阅区，复用已配置的会话连接。请求包含原图、当前绑定装配、带编号枢轴的分件图、目标姿态图，以及有图的最近前后姿态。模型按当前骨骼的父子坐标关系估计完整 R/B/X/Y，保持骨骼结构不变。可在并排预览中比较目标图与提案，描述修改后继续请求，最后「采纳姿态目标」。提案未采纳时不修改工程；响应期间改动姿态、骨骼、源图或动作会使旧提案失效。不确定部件会单独列出。

审阅区还会用生产网格渲染器绘制当前/提案姿态，把目标图透明背景或可分离的纯色背景变成前景轮廓；两侧按前景外接框等比居中后，可调透明度叠看，并显示轮廓重合率。无法可靠分离背景时不计算该数值。此数值仅衡量归一化后的形状重叠，不能解释部件身份、遮挡、重绘纹理或真实坐标误差，需继续人工检查方向、连接和遮挡。

「本地姿态微调」可从当前手工目标或 AI 提案开始，勾选允许转动的部件，指定最大角度改动（±5/15/30/60°），再点击「按目标图微调」。默认选择子部件，根部件保持局部角度；没有子部件时默认全选。可另选允许柔性部件弯曲，刚性部件不会增加弯曲。优化重用生产渲染器，每次比较 256×256 的归一化前景，误差为 75% 轮廓不重合率加 25% 重叠区域平均 RGB 差异。位移、贴图、绑定和层级固定，未选部件仍会跟随父骨骼运动。它是有范围限制的局部搜索，无法解决错误贴图、翻面、新遮挡或全局运动估计，也不保证全局最优或跨帧连贯。

微调支持取消、查看前后误差、恢复微调前姿态，点击「采纳姿态目标」才会写入工程；采纳后依旧能手工编辑、保存和插帧。期间编辑或切换工程会丢弃旧结果。继续会话时还会附上当前骨骼提案的实际渲染图，让模型依据已渲染的姿态调整。轮廓与图像误差是单张图片的比较数值，不能当作动画质量或真实关节准确率。

## 第二版：从整图到骨骼

### 直接导入拆层结果

点击「导入图层清单」，同时选择一份 JSON 和其引用的 PNG。支持 See-through `SavePSD` 的 JSON 字段，也支持本项目输出节点的清单。本版文件选择器使用同目录文件名匹配：请将所需 PNG 和清单放在同一目录，清单的 `filename` 使用文件名；嵌套目录文件选择尚无专门入口。

```json
{
  "width": 1000,
  "height": 800,
  "layers": [
    { "name": "body", "filename": "body.png", "left": 300, "top": 300, "right": 650, "bottom": 650, "depth_median": 0.8 },
    { "name": "face", "filename": "face.png", "left": 310, "top": 60, "right": 630, "bottom": 340, "depth_median": 0.2 }
  ]
}
```

这里 `body.png` 必须为 350×350，`face.png` 必须为 320×280。PNG 尺寸与裁剪框不一致会被拒绝，不会拉伸图片或猜测偏移。数组顺序就是从后到前的绘制顺序，不会再次按深度排序。重组预览使用原始 PNG；纹理超过 1024 像素时仅等比缩小整个裁剪图，保留其坐标含义和原始 PNG。

审阅时可以选择 1–24 个图层，并修正动作角色和父骨骼。名称/位置推断仅是建议，例如面部零件优先跟随头部；不会自动推理真实关节。全透明图层默认不选，取消父图层会将子图层改挂 root。骨骼循环会报错。确认后创建新的可编辑工程，原工程保留。

支持读取 1–128 层清单、最大 8192 像素单边 / 32 MP 画布，单原始 PNG 至多 16 MiB。清单至多 1 MiB，准备阶段图像数据总量至多 64 MiB，创建工程时还需符合 48 MiB 的工程图像总量限制（按 data URL 长度计，包含原始图和工作纹理）。

### 连接本机 ComfyUI

1. 按 [输出节点安装说明](../modules/spine_comfy_bridge/README.md) 准备 ComfyUI、See-through 模型和本项目节点。此版本没有自动安装或打包模型权重。
2. 在 **桌面版** 点击「本地 AI 拆层」，填写本机 HTTP 地址，默认 `http://127.0.0.1:8188`，然后「检查连接与模型」。只接受 `127.0.0.1`、`localhost`、`[::1]`，不能使用远程地址、登录信息或子路径。
3. 选择拆层/深度模型。模型选项来自 ComfyUI，选项出现不等于权重已经安装。需要支持 `auto_download` 的节点版本；流程明确关闭模型自动下载和 LaMa。
4. 上传整张角色图，或「从生图历史选择原图」。输入保留完整画布，最长边缩至 2048。默认 768、30 步、NF4、分组卸载开启可作为首次试跑参数；本机 12 GB 显存是否可行仍需真实推理确认。
5. 开始拆层。作业 ID、参数、状态与回执持久化到独立 IndexedDB `levelup-spine-local-jobs`。面板打开时每 5 秒串行刷新运行中作业，查询失败后间隔 30 秒；关闭面板或切换工作区暂停刷新，ComfyUI 推理继续。
6. 完成后点击「检查图层并创建骨骼」。下载属于该作业的 PNG，进入上述重组审阅，然后创建新工程，后续编辑和导出与第一版一致。

### 中断与恢复

- 提交前先保存检查点。重启时尚在准备的作业标为中断失败，未拿到回执的提交标为待确认。
- 「找回提交回执」查本机队列和最近 100 条 history；找到后按 prompt ID 读取结果。网络错误或未找到记录均不会自动重发推理。
- 已有回执的任务可「刷新任务」。长时间无历史记录可能是仍在排队，也可能是 ComfyUI 清理了历史，应打开其界面检查。
- 「停止跟踪（不取消推理）」只停止该作业的自动查询、释放工作台的新任务入口；服务端可能仍在计算。可以再刷新/找回。需要真正取消时，在 ComfyUI 中确认具体任务再操作，工作台不会调用全局 interrupt。
- 回执和 manifest 不包含输出图片副本。审阅前需保留 ComfyUI output 文件；创建工程后，所选原始图与工作纹理会随工程保存，不再依赖 ComfyUI。
- 本机服务断开、缺节点/模型、显存不足、清单异常、输出图片被删除都会显示错误；不会在失败时创建空工程。

## 输出与能力边界

| 输出 | 用途 |
| --- | --- |
| `skeleton.json` | Spine 4.2 JSON，含骨骼、slots、default skin、加权网格和骨骼动画 |
| `skeleton.atlas`、`atlas-*.png` | 运行时纹理图集，直通 Alpha，2 像素留边，边缘像素扩展 |
| `images/*.png` | 编辑器导入使用的独立部件贴图 |
| `project.levelup-spine.json` | LevelUpAgent 可重新打开的自包含工程，重新导入创建副本 |
| `sources/layers.json`、`sources/*.png` | 通过图层清单导入时的原始裁剪素材和坐标，按当前保留图层输出；原始文件名保存在工程 provenance 中 |
| `sources/source.png`、`sources/source-cutout.png` | 工程中上传/生成的原始整图，以及存在时的纯色背景处理结果 |
| `README.txt` | 导入方法、资产版本和部件名称/ID 映射 |

每个部件由 25 个顶点、32 个三角形、基础骨骼和末端弯曲骨骼组成。权重在枢轴以下逐渐增加，界面可以调整末端骨骼影响比例；更细致的逐顶点权重、骨骼结构和拓扑可在 Spine 中继续编辑。预览和导出共用同一套姿态采样与线性混合蒙皮逻辑。

目前支持 24 个部件、16 个动作、每个部件每个动作 300 个关键帧，单动作 0.1–30 秒。工程中的 PNG 数据总量限制为 48 MiB，ZIP 编译结果限制为 64 MiB。保存失败会显示错误，仍可从内存中的工程导出备份。

当前版本不支持导入任意第三方 Spine JSON/二进制工程，不包含 IK、物理约束、皮肤切换、网格 deform 轨道或贝塞尔曲线编辑器。不要通过修改版本字符串把此格式当作 Spine 4.3 使用。拆层后仍需检查部件完整性并调整枢轴；像素动画需要姿态拟合才能转成可编辑骨骼曲线。

## 实现位置

- `src/components/SpineStudio.tsx`：工作台、生图接口接入、工程和编辑状态。
- `src/components/SpineCanvas.tsx`、`src/lib/spineRenderer.ts`：WebGL 贴图网格预览、骨骼/网格叠加和拖动。渲染器为本项目实现，不打包 Esoteric 官方运行时。
- `src/lib/spine.ts`：工程校验、骨骼层级、加权网格、姿态采样、动作预设、Spine 4.2 编译器和图集布局。
- `src/lib/spineGeneration.ts`：串行生成、逐部件保存检查点、停止后续请求。
- `src/components/SpineLayerImport.tsx`、`src/lib/spineLayers.ts`、`src/lib/spineLayerAssets.ts`：拆层契约、几何重组、原图保留、绑定建议与审阅。
- `src/components/SpineComfyPanel.tsx`、`src/lib/spineComfy*.ts`、`src-tauri/src/spine_comfy.rs`：本机 ComfyUI 固定图、回执持久化和恢复；`modules/spine_comfy_bridge/` 为输出节点。
- `src/lib/spineAssets.ts`：图片标准化、透明度检查、图集绘制、可离线使用的示例。
- `src/lib/spineStorage.ts`：IndexedDB 工程和摘要存储，不把图片放入 localStorage。
- `src/lib/spineArchive.ts`、`src/lib/spineBridge.ts`、`src-tauri/src/spine.rs`：ZIP 打包、浏览器下载和桌面保存。桌面端检查文件类型、ZIP 路径、条目数与大小，先写临时文件再替换目标文件。

## 本地 RIFE 参考帧（V5）

桌面版的多图关键姿态面板新增「本地像素补帧（RIFE）」。指定本地 `rife-ncnn-vulkan.exe`、`rife-v4.6` 模型目录和 GPU 编号，将时间设在两张姿态图之间，可均匀生成 1/3/7 张参考图。输入保持完整画布、统一到最长边 512 像素，两端宽高比必须一致。RIFE 只处理 RGB，透明区域先合成浅灰，原有纯色背景保留。

结果先写入姿态研究，初始骨骼目标只是两端目标的插值，尚未从像素识别。继续使用 AI 识别、局部拟合和人工审阅，再插帧为新动作。图像误差改善不能保证骨骼角度正确；小鸟实测出现过误差分数下降、左翅角度反而偏离的情况。端点或生成时间变化会使批次失效，无关的捕获姿态及设置编辑保留；批次失败不写入，停止后续补帧则在当前帧结束后保留本批完成帧。

程序与模型不随应用打包。当前本机研究程序位于 `G:\Work\LevelUpAgent\research\spine-tools\rife-20221029\selected\rife-ncnn-vulkan.exe`，模型目录为 `G:\Work\LevelUpAgent\research\spine-repos\rife-ncnn-vulkan\models\rife-v4.6`。Tauri 使用固定参数数组执行，验证本地路径、模型文件、PNG 大小和尺寸，单次只运行一个 RIFE 进程，超时 90 秒后终止。

# 摇光残影自动机器人（网关协议 v1）

入口：**摇光残影 → 自动机器人**。复用已配置的模型连接，每个残影对应一个永久机器人 ID；当前显示哪个形象，不影响其他机器人的工作。

2026-10-20 新增 **钉钉桌面接管（实验）**：不需要开发者或组织 API 权限，使用已登录账号、本地 OCR 和 UIA。版本仍为 1.3.82；[桌面接入说明与验证边界](DINGTALK_DESKTOP_2026-10-20.md)。以下官方 API 通道的权限要求不适用于桌面通道。

开发状态（2026-10-19）：按用户确认，本地实现与验收已完成；实际平台应用开通和真实收发联调留待后续。代码位于本地工作树，尚未发布。可在主工程运行 pnpm tauri dev 查看，pnpm dev 仅为前端预览。[本地验收记录](CHATBOTS_LOCAL_ACCEPTANCE_2026-10-19.md)

## 首次使用

1. 在应用设置中配置模型连接。支持现有 OpenAI Chat / Responses、Anthropic、Gemini 协议。
2. 选择残影，设置名称、专属模型、自定义人格和限额，保存身份。
3. 平台账号页自动识别本机 **Python 3.10+（含 venv/ensurepip）**，点击“使用已有 Python 配置依赖”。无需重装 Python；只在应用数据目录 chatbot-runtime-v1 安装独立 SDK 环境，不修改系统 Python。首次依赖安装需访问 PyPI，已有环境通过校验后直接复用。未识别时可重新检测或手动选择已有的 python.exe。钉钉桌面通道另需 **Windows Python 3.10–3.12 x64**。
4. 添加平台账号，在密码框填写 App secret / Client secret / OneBot token。密钥存入系统凭据管理器；编辑时留空保留密钥。
   账号保存与连接结果分开显示：未安装环境或未填写密钥时仍保存账号，卡片显示 setup_required / credential_required；补齐后重连，无需重新新建账号。
5. 开通下表权限并连接账号。给机器人发一条文本，在“收发记录”中点击“绑定到当前机器人”。检查聊天类型、ID 和话题 ID 后保存。
6. 在“知识库”中粘贴资料或导入 UTF-8 TXT / Markdown，设置机器人全局或单个聊天的可见范围。人物关系记忆额外绑定发言者 ID。
7. 开启自动答复，再次发消息验证。首条用于识别聊天的未绑定消息不会追溯执行。

## 行为与边界

- 回复范围：在“聊天范围与路由”中分别管理私聊和群聊，勾选指定聊天、全选列表或取消全选，再应用。列表来自已有路由、最近收件记录及手工登记，并非完整通讯录；取消勾选并应用会暂停该聊天。群默认仅 @，支持的通道可改为全部新文本。
- 全部范围：官方/API 与 OneBot 通道可设置账号全部私聊或全部群聊，包含以后收到的新聊天；仍受平台权限与机器人可接收范围限制，不代表接管个人账号的所有聊天。精确聊天/话题设置优先，包括已暂停或所属机器人已停用的规则。钉钉桌面不支持自动发现全部聊天，只支持登记列表全选，每账号最多 100 个标题；[build6 范围说明](CHATBOTS_SCOPES_2026-10-20.md)。
- 独立身份：人格、模型、知识、人物记忆、历史、用量按机器人隔离。会话键还包含租户、账号、真实聊天和话题；全部规则下的不同聊天也不共享会话历史。群内共享最近会话；人物记忆仅匹配当前发言者，须绑定精确聊天规则。
- 有限能力：仅使用本次聊天和授权资料。不继承主 Agent 的终端、文件、MCP、技能、目标或主人记忆。资料以引用数据提供，不作为系统指令。
- 知识检索：先按机器人/聊天 ACL 筛选，再按 1,200 字片段做词语/中文双字相关度排序，最多 5 段；单条 100 KB，每机器人 20 MB。当前不是向量库，不支持 PDF/OCR。修改/删除知识取消该机器人在途生成与未发送回复。
- 消息可靠性：SQLite 提交后确认可确认的平台回调。平台消息 ID 在账号范围去重；飞书使用 message_id。QQ 提交失败后回滚恢复序号。OneBot 没有统一事件 ACK/历史重放保证，离线补发取决于外部服务。
- 顺序与预算：同会话按入库顺序生成和发送；全局最多 2 个生成任务、500 条待处理消息。每机器人每日请求上限按 UTC 日界，默认每天 100 次、冷却 2 秒。超额记为 rate_limited。单次输出最多 4,096 tokens、90 秒；公开回复最多 1,200 字符；最近 12 轮已送达历史。删除历史不重置限额。
- 收发分离：生成结果先存发件箱。发送失败不重新生成。不确定发送记为 delivery_unknown，阻塞该会话后续生成，直到主人核对平台后“确认送达”或“放弃”；不自动重发。
  收发记录通常显示最近 200 条；全部未解决的 delivery_unknown 额外保留并置顶，不会因新消息过多而失去核对入口。
- 人工接管：暂停机器人/聊天取消排队生成和未发送回复，模型请求按 200ms 周期检查取消。发送认领与接管串行化；已提交网关/平台的消息无法保证撤回。
- 重启：已认领生成标记 interrupted，不自动重复消耗；待发回复可继续；发送中变为 delivery_unknown。钉钉回复 URL 不落盘，进程重启后缺少上下文的待发回复标为失败。
- 生命周期：每账号独立子进程、stdin/stdout 通信，无本地 HTTP 监听。断线退避 2–30 秒；应用退出终止网关。密钥不进入命令行、数据库配置或日志。聊天内容由用户所选模型服务处理。
- 清理：断开账号后可移除系统密钥、路由、专属资料和记录。清理机器人聊天保留去重标识。聊天历史不会自动公开为知识。

## 故障排查

| 状态 | 处理 |
| --- | --- |
| setup_required | 安装 SDK 环境；Python 需带 venv |
| credential_required | 编辑账号并填写有效密钥 |
| connecting / reconnecting | 检查应用开通、权限发布、网络；OneBot 检查端口、token、登录账号 |
| unrouted | 绑定精确聊天；之后的新消息才会答复 |
| unsupported_media | 改用文字；当前不解析媒体 |
| rate_limited | 检查请求上限/冷却，或等待下一 UTC 日 |
| failed | 检查生成错误、平台权限、回复有效期 |
| delivery_unknown | 到平台核对后标记；不要盲目重新发送 |

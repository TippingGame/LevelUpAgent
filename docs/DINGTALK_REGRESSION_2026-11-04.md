# 钉钉桌面回归排查（2026-11-04）

用户报告 1.5.86 窗口漏检，以及在两台电脑上出现建立基线、草稿等待和在线状态却未自动回复。

## 本轮已复现并修正

- 草稿图像原先直接使用保存的校准矩形。默认坐标或旧坐标包含侧栏、工具栏时，即使真实输入框为空也会判定非空。现在先定位唯一 UIA 编辑控件，再只检查其实际边界内的图像；越界、截图期间尺寸变化和不可识别的真实草稿仍阻止发送。
- 尚未校准的默认区域不再直接用于自动收发。扫描和发送均先尝试原生控件校准；不支持的客户端明确要求手动校准。已保存的自定义校准不被替换。
- 连续空 OCR 帧原先清掉上一帧消息指纹，随后恢复的“旧消息 + 新消息”无法匹配前后关系，新消息会被吞作基线。现在保留最后可比较的指纹；仍要求两次稳定观察、方向检查和历史去重。
- 空消息识别结果显示等待和校准提示；正常监听状态显示收到/总消息数量、群聊提及触发条件，基线提示说明历史消息不回复。
- 用户恢复本机窗口后，在实际聊天 `222` 复现新版客户端兼容故障：输入框改为无名称的 `im_chat::InputRichTextEdit`，发送按钮名称为 `发送(S)`，聊天列表为 `ConvListItemListView`。现在兼容这组已观察到的控件，同时保留唯一性与几何关系核对。
- 新版空输入框内显示浅灰色“请输入消息”，旧检查会将其判为草稿。现在只有已核对的原生输入框、空 UIA 值、精确提示文字、左上角几何及浅色像素同时满足时才视为空；聚焦时只排除已核对的原点单列深色光标。深色同名草稿、额外内容、未知控件仍阻止发送。
- 新版消息气泡尾部落在旧头像过滤范围内，实机此前仅识别到 1 条发出消息、0 条收到消息。调整头像边缘范围与短气泡均匀色占比后，可识别 6 条完整消息（收到 3 条、发出 3 条）；顶部被裁切的消息仍排除。

## 新版客户端发送兼容

原 R2 只修复了读取，不能作为新版客户端的完整发送修复。实测后台 `WM_CHAR` 未进入新编辑器；改投新 Qt 子窗口会激活钉钉，无法满足后台模式“不抢前台”的行为。实验改动已经撤回。

1.5.87 增加明确选择的「前台兼容模式 · 新版钉钉」，发送前等待键鼠空闲 5 秒并激活钉钉。它接受所选窗口内的原生子窗口焦点；核对标题、草稿、窗口位置、人工输入与发出气泡。已有草稿在记录发送意图之前进入等待，保留回复排队；输入后结果不明不自动重发。读取稳定的当前聊天可在后台进行。旧账号保持后台模式，连接运行时不能直接切换模式。

用户授权的第一条测试消息由用户手动发送，不计作自动发送成功。第 2 条固定消息经生产前台驱动自动发送成功：只点击一次发送，核对新增发出气泡和空输入框。证据保存在本地 `artifacts/dingtalk-regression-20261104/foreground-send2-after-caret-fix.json`，截图与聊天内容不提交仓库。

第 3 条固定消息通过实际 `desktop_gateway.py` 子进程 IPC 和 `inputMode: foreground` 自动发送成功：单次发送请求，持久化意图最终为 `sent`，新增发出气泡和空输入框均通过核对。启动时自动校准默认区域、两轮稳定观察建立基线，不回放历史消息；测试结束关闭 stdin，子进程退出。证据为本地 `gateway-send3.json`。

## 复测与边界

新版客户端：暂停连接 → 发送方式选「前台兼容模式 · 新版钉钉」→ 自动识别区域并预览 → 核对输入框为空及消息方向 → 保存并连接。保持钉钉打开且不最小化，等待基线建立后从对端发送新文本，并让键鼠空闲。首次基线里的旧消息不会回复，群聊仅提及模式须使用配置中的准确显示名。

后台模式继续适用于此前支持定向输入的客户端。前台兼容模式会占用前台及输入设备，不能承诺用户同时操作时自动回复。

本地发出气泡仅证明客户端接受了发送，不代表服务器或对端确认。当前完整的「实际入站 → 模型调用 → 自动发出」与另一台电脑的 `111` 仍需实机验证；不能把本机固定消息发送成功扩大为两台电脑全链路已通过。

# 聊天选择与全部范围（build6，应用版本 1.3.82）

本构建响应“选择私聊/群聊、分别全选，以及后台静默回复”的需求。增加范围设置，保持应用版本 **1.3.82**；不覆盖 build1–5。

## 使用

进入“摇光残影 → 自动机器人 → 聊天范围与路由”，选择当前残影的机器人和平台账号，分别管理私聊或群聊。

1. 列表包含已有路由、最近收件记录及手工登记的标题/ID。逐个勾选，或使用“全选列表”，然后“应用列表选择”。全选包含筛选后暂时隐藏的项；其他机器人拥有的聊天不能直接覆盖。
2. 取消某项勾选并应用，会暂停该聊天。取消全选并应用，可以批量暂停列表。保存是事务操作；发生冲突时整批回滚。
3. 群聊另选“仅 @ 我”或“全部新文本”。后者仅在通道支持时提供；QQ 官方、钉钉官方仍限机器人 @ 消息。飞书全部群消息需要额外权限。
4. API/OneBot 通道可以勾选“此账号全部私聊/群聊”，再保存全部范围，覆盖该通道以后实际接收的新聊天/话题。精确设置优先，包括暂停项，不会被全部规则绕过。全选受平台授予的接收范围限制。
5. 钉钉桌面仅支持已登记列表全选，最多 100 个标题/账号。需要完整且唯一的标题在钉钉侧栏可见；无法可靠发现完整通讯录或自动接管以后所有新聊天。“全部未来聊天”选项禁用，后端和驱动也拒绝此配置。

## 后台限制

钉钉桌面通道仍是前台可视接管：会切换聊天、读取画面和输入答复，需要 Windows 解锁、钉钉未最小化、画面可用，并等待键鼠空闲。UIA 在当前客户端不能可靠完成静默写入，删除空闲保护会干扰用户操作，不能将其作为后台方案。

希望日常电脑不被占用，可把该通道运行在专用电脑或独立虚拟机中，保持其桌面解锁可用。官方机器人/API 能后台接收事件和发送，但需要申请权限，且不能等同于以个人账号读取任意聊天。

## 隔离与兼容

- 旧路由默认 `scope=exact`；`scope=all` 与群内 `mode=all` 分别表示聊天范围和消息触发，不混用。
- 单独设置始终优先；新增精确排除项时取消旧全部规则匹配的在途生成/待发回复。已经提交给平台的发送不能撤回。
- 全部规则仍按真实聊天/话题隔离历史，不把不同人的上下文合并。人物记忆必须绑定精确聊天；全部规则的显式知识授权可用于其覆盖的聊天。
- 本轮没有启动真实钉钉监听或向真实聊天发送。build5 的“测试”群 @ 自动回复证据见 [群聊实机记录](CHATBOTS_GROUP_ACCEPTANCE_2026-10-20.md)，不能代替新增多聊天/群全部文本的实机验收。

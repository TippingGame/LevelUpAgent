# 工作台依赖移除与图片历史性能验证

验证日期：2026-10-16。此功能纳入 1.3.80，正式发布状态见 [发布记录](RELEASE_1.3.80.md)。

## 功能范围

- 音频：「环境与下载 → 选择模型 → 移除已安装依赖 → 确认移除」。仅清理该引擎当前资源版本及其安装缓存，支持未完成安装的清理。
- 3D：「环境与下载 → 移除已安装依赖 → 确认移除」。清理当前平台、当前资源版本的全部组件和缓存；不删除其他平台或旧 WSL 资源。
- 两者都保留作品、历史、参考文件和原始离线包。生成 / 排队 / 安装时阻止移除；文件占用等错误可重试。
- 音频最后一个运行环境移除后，直接从 SQLite 读取已有作品，重启后仍可试听、导出 WAV。

## 图片输入性能

历史原本按 24 条分页，但输入提示词仍会重新执行全部已加载卡片。现在缓存列表派生数据，以稳定事件分发配合 `memo` 隔离输入和历史；事件仍使用最新引用和编辑状态。图片增加延迟加载、异步解码，屏幕外卡片跳过布局和绘制。

同一 React 开发版 Profiler 场景，1920×1080、连续输入 31 个字符、每字间隔 25ms。旧版组件和 CSS 从 Git HEAD 提取，两版使用相同函数入口计数与性能采样：

| 已加载历史 | 输入期间渲染总耗时，修改前 → 后 | 单次最高耗时，修改前 → 后 |
| --- | --- | --- |
| 24 张 | 293.2 → 125.1 ms | 25.7 → 5.2 ms |
| 240 张 | 1,370.8 → 132.6 ms | 123.4 → 4.7 ms |

修改后输入期间历史卡片函数调用为 0。此对比使用 SVG 测试图片，数字是 React 渲染耗时，不是所有设备的输入延迟保证。

另在真实 Tauri release / WebView2 中最大化窗口，加载 240 张 1536×1536 本地 JPEG。四种外观的输入测试均未记录到超过 50ms 的主线程长任务，历史卡片无 DOM 变更。检查了加载更多、滚动后图片解码、大图前后导航、展开 / 复制提示词、连续复用不同图片、进入编辑画板和删除作品。实际输入法、不同显卡 / WebView 版本的体验仍以用户设备为准。

本地证据：`artifacts/workbench-removal/` 中的 `before.json`、`after.json`、`native.json`、`media-native.json`、`removal-guards.json`、`restart.json`、截图和检查日志。测试脚本与大文件保留在忽略的 artifacts 目录。

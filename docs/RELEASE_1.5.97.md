# v1.5.97：空输入栏误判草稿修复

- 修复已经进入目标会话，却停在“当前聊天输入框未确认空白”的问题：手动框选输入栏包含边框、工具栏或发送按钮时，优先定位唯一且位置相符的真实编辑控件，检查完整编辑区，避免把外围图标当作草稿。
- 继续使用保存的截图和框选坐标定位，不改写校准；没有唯一匹配的编辑控件时，保留原区域识别。检查完整编辑框也避免较小框选漏掉已有草稿。
- 实时识别和发送等待提示区分提示文字未核验、未识别内容与识别到文字；控件读取失败时保留原回复等待，不再笼统要求“先处理草稿”。
- 前台兼容和后台模式共用修复。真实草稿不覆盖，发送前标题与回复文字核验、发送结果不明不自动重试等保护保留。
- 沿用现有账号、聊天路由、截图、框选区域和执行模式；音频及 3D 独立资源继续复用。

## 升级与验证范围

退出旧版后安装 1.5.97，再启动应用。输入栏应框住纯文字编辑区域，排除表情／附件工具栏和发送按钮；窗口尺寸或内部布局变化后需要重新校准。目标聊天已有真实草稿时仍需处理草稿，程序不会覆盖后自动发送。

使用之前授权测试保存的钉钉截图和同次编辑控件边界，完成离线真实 OCR 对照：1.5.96 将含工具栏的空输入区误判为非空，修复后正确识别为空。自动回归覆盖前台和后台从空栏检查到输入、发送和回执的流程，但不等同于真实客户端收发测试。

本轮窗口工具返回归属错误，未完成当前钉钉实机操作验证，也未向联系人发送新消息；另一台问题电脑需要升级后复测。旧版已进入“送达待确认”的记录不会自动重发，请先在聊天软件核对后处理。

详细行为见 [桌面截图校准说明](DESKTOP_CALIBRATION.md)。本地验证证据位于 `artifacts/desktop-editor-review/` 和 `artifacts/release-1.5.97/`，私人截图不提交。

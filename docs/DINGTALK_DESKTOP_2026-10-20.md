# 钉钉桌面接入测试版（1.3.82，2026-10-20）

> 本文保留历史测试记录。1.4.83 已改为后台窗口定向收发，本文中前台输入与键鼠空闲限制仅适用于旧构建；当前行为见 [后台验证](DINGTALK_BACKGROUND_1.4.83.md)。

本次保留应用版本 **1.3.82**，以单独测试安装包和本记录区分构建。build1–3 为此前本地验收；build4 开始在用户已登录的真实客户端验证区域校准、动态读取及限定私聊回复。实测结果见 [build4 实机记录](CHATBOTS_LIVE_ACCEPTANCE_2026-10-20.md)。群 @ 的 build5 修复与真实验收边界见 [群聊记录](CHATBOTS_GROUP_ACCEPTANCE_2026-10-20.md)。

## 接入方式

新增平台 `dingtalk_desktop`。控制 Windows 已登录的钉钉桌面客户端，使用本地截图、OCR、Windows UI Automation 和文字输入，不调用钉钉开放平台、不使用 dingtalk-workspace-cli、不要求 AppKey、AppSecret、开发者或组织 API 授权。钉钉仍需由用户正常登录。消息以该登录账号身份发出；多个残影是应用内部的独立人格，并不会创建多个钉钉账号。

每个残影继续使用自己的模型、人格、知识和白名单聊天路由。本机只允许一个钉钉桌面控制账号，避免多个进程争抢窗口；它可以把不同聊天分配给不同残影。聊天文本仍会送往所选模型服务。

## 测试步骤

1. 安装测试包；进入 **摇光残影 → 自动机器人 → 平台账号**，添加平台 **钉钉桌面（无需开发者权限）**。
2. 页面自动检测本机已有 **Windows Python 3.10–3.12（x64，含 venv/ensurepip）**，显示版本和路径。点击“使用已有 Python 配置依赖”，无需重新下载安装 Python。首次只联网下载机器人依赖，在应用数据目录 `chatbot-desktop-runtime-v1` 创建独立环境，与官方 SDK 环境隔离。已就绪后点击“校验已有环境”，通过则直接复用，不重建或重复安装依赖。若没有识别，可重新检测或展开“手动选择 Python”选择已有的 `python.exe`；支持中文和空格路径。只有 3.13+、32 位或 ARM64 Python 时，需另装兼容的 x64 版本，可与原版本共存。
3. 正常打开并登录钉钉，保持 Windows 解锁、钉钉窗口可用且不最小化。输入自己的准确 @ 显示名；不同群别名用逗号分隔。
4. 先检测并选择钉钉窗口，点击“自动识别区域并预览（不发消息）”。程序从客户端可访问控件识别标题、消息区、输入框、列表及发送按钮，自动填写坐标；核对识别正文和方向。未知结构或控件不唯一时停止，仍可用截图手动校准。默认坐标只是参考。查看“输入框只读检查”：无法读取时不可发送；有草稿时先自行处理。检查不聚焦、不输入、不发送，也不展示草稿正文；截图预览只留在界面内存。
5. 核对识别标题、方向和正文。保存账号，在“聊天范围与路由”选择账号和私聊/群聊，逐行登记**完整且唯一的聊天标题**，勾选目标后应用；支持全选列表和批量暂停。空格、括号人数必须一致；截断或同名聊天不得用猜测代替。列表不是完整通讯录，每账号最多登记 100 个标题；将少量测试聊天置顶，保持完整标题可见。
6. 保存并开启残影身份及账号连接。启动后的首次两次一致观察仅建立基线；等监听状态稳定后，从另一个测试账号发送新文本。私聊处理新文本，群聊默认仅处理准确 `@显示名`，可明确选择“全部新文本”；群选择范围与群内触发方式分别设置。
7. 先验证一个私聊，再验证一个测试群。接管会切换聊天、占用键鼠，请使用专门空闲的 Windows 会话。人工输入时等待空闲；人工接管按钮、暂停机器人、断开账号可停用。
8. `delivery_unknown` 表示没有足够可见证据确认发送，可能已发出，也可能仅留下草稿。先在钉钉核对，再确认送达或放弃；程序不会自动重发。

## 实现与边界

- **不能后台静默收发**：当前驱动需要切换钉钉聊天、可见画面和前台输入。发送前必须等待键鼠空闲；不能通过取消此保护保证后台发送。最小化、锁屏和其他窗口遮挡不受支持。建议使用专用电脑或独立虚拟机并保持其 Windows 桌面解锁可用；虚拟机本身仍需运行可见桌面。官方机器人/API 可在后台工作，但需要对应权限，且消息身份和接收范围由平台规定。
- build6 的指定聊天、列表全选和群全部文本设置见 [范围与验收记录](CHATBOTS_SCOPES_2026-10-20.md)。本轮本地模拟验证不替代真实客户端的多聊天轮询与群全部文本验收。
- 接收：两次一致画面后比较重叠序列；首次、无重叠、重启和恢复路由重新建立基线。最近 500 条画面签名帮助避免滚动重放；不能代替平台消息 ID，不能承诺不漏消息或严格恰好一次。
- 本地缓冲与序列原子写入，收到主进程 SQLite 提交 ACK 后移除。待确认消息绑定原路由和机器人，重新绑定不转投旧消息。
- 空聊天在完成稳定基线后可以接收第一条新消息；已有历史的 OCR 暂时变空不会重新投递历史。
- 文字识别：仅接收明确气泡背景和方向的高置信 OCR；过滤普通昵称、时间及大部分图片文字。检测仍属启发式，无法保证所有主题、引用、长消息、表情和卡片。
- 群身份：画面无法可靠认证发言者，使用每事件独立的未核验 sender ID，避免不同群成员共用人物记忆。群内历史仍共享。
- 发送：核对窗口、标题、空闲桌面、可读且空的输入框；持久化发送意图；写入后核对草稿、焦点、位置、输入状态；点击一次发送；新增同文发出气泡且草稿清空才记为 sent（本地已发出），不代表服务器或对方回执；离线和失败状态仍需在钉钉核对。
- 开始输入前遇到人工活动，保留同一条已生成回复排队，空闲后再尝试，不重新请求模型；若已记录发送意图，则保持 `delivery_unknown`，不自动重试。暂停机器人或路由时仍取消待发回复。
- 不把模型文字交给按键语法解析器。优先 UIA ValuePattern 或 LegacyIAccessiblePattern 直接设置文本；备用逐字 Unicode 输入不解析 `{Enter}` / `{Ctrl}`；备用输入无法安全处理多行时拒绝发送。设置器部分写入后报错也会核对草稿，防止再次追加回复。
- 输入前再次读取聊天标题，点击前核对窗口位置、鼠标位置和点击点实际所属窗口；遮挡、焦点改变或人工输入会停止操作。
- UIA 无法识别或读取输入框、未知草稿、标题无法匹配时停止。所有钉钉版本不保证开放相同 UIA 控件。
- build4 实测发现 UIA 返回空值不代表输入框真的为空，现以画面内容交叉检查。输入框中的可见文字必须与预期精确匹配（忽略空白、统一全半角），否则保留草稿并停止。多倍 OCR 仅用于复核，不能保证所有字形和标点。
- 稳定性定位：这是实验性的桌面可视接管，不具备官方事件 API 的消息 ID、完整历史或成员身份认证。自动校准按钮只在用户执行时更新区域，并非后台不断自动适应布局。切换布局、缩放、主题或升级客户端后，应断开账号、重新校准并核对预览；未知结构停止。
- 群 @ 判断来自识别出的可见文字，无法区分平台真实 mention 元数据与普通文本仿写的 @ 名称；仅用于触发回复，不作为身份或权限证明。
- 未确认发送不重试；主进程退出或崩溃关闭 stdin 后子进程退出。
- 聊天参与者不获得主 Agent 的文件、终端、工具、MCP 或主人私有记忆。

## 验证范围

- Python：规则、持久化缓冲、私聊/群 @、去重、自发排除、滚动、重启发送保护、焦点/草稿/回执、合成图像气泡过滤。
- 实际子进程的 NDJSON 协议测试：丢失 ACK 后重投同一消息 ID、人工操作延后发送、未确认发送跨重启不重试、驱动阻塞时 stdin EOF 仍退出。驱动为专用测试模拟，不属于真实钉钉验收；模拟脚本不随安装包分发。
- 用户真实钉钉截图本地 OCR：保留可见文字气泡，排除表情图文字。截图不能验证动态接收、UIA 输入、发送或送达。
- 原生 QA 使用专用 `com.levelup.agent.chatbotsqa`，本地模拟模型/平台；验证无密钥桌面账号、独立运行环境、真实 Windows 窗口枚举、无窗口时等待、路由及四套外观。执行结果以 `artifacts/chatbots-review/report.json` 为准。
- **build1–3 历史结论：当时用户尚未打开客户端，未验证动态监听及实际发送。** build4 的真实测试单独记录，不把此前模拟测试追溯标记为实机通过；群 @、不同主题、不同 DPI 和客户端版本仍需进一步测试。

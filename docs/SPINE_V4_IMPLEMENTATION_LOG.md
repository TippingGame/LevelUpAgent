# Spine 第四版实施日志

日期：2026-10-04。目标：让单张角色图进入现有 Spine 工作台，保留原图、提供本地去纯色背景、将整图传给拆层和逐部件生图流程，并用会话提出可编辑骨骼与动作修改。最终资产仍是 Spine 4.2 JSON、图集、PNG 和可重新打开的 LevelUpAgent 工程。

## 01 · 整图入口

- `src/lib/spineSource.ts` 将上传或生图所得整图标准化为最大 2048 像素边长的 PNG，保留完整画布和原图，不裁去透明边缘。源图在 `SpineProject.sourceImage` 中随 IndexedDB 工程保存。
- 工作台支持上传整图、调用已有生图连接生成整图、从生图历史选择整图。本地“去纯色背景”仅在四角颜色相近时，从画布边界对相近颜色做连通区域抠图；原图保持不变，可一键还原。它不是语义抠图，也不会重建被遮挡的肢体。
- 源图是“补齐六部件”的默认身份参考。用户主动选择的参考图仍优先；已有部件不会被替换。打开本机 AI 拆层面板时，工程整图会作为初始输入。

## 02 · 会话提案与持久化

- `src/components/SpineAssistantPanel.tsx` 使用用户已配置的文本模型和现有 `agentTurn`，把当前部件几何、动作和可用整图送入会话。请求和简短回复存入 `SpineProject.rigConversation`，最多 80 条。
- 模型只提出 JSON 草案。`src/lib/spineAssistant.ts` 将其解析、校验现有部件 ID、父子关系、尺寸、枢轴、动作轨道和工程限额；用户点击“应用方案”后才写入骨骼和动作。切换工程后旧回复不会写入新工程。
- 会话不能凭空创建贴图或还原遮挡区域。需要先用本机拆层或逐部件生图得到真正分开的透明贴图，骨骼调整才有实际效果。

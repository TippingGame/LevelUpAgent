# Spine 第三版实施日志

日期：2026-10-03。目标：在现有 Spine 创作工作台中加入多图关键姿态、可编辑目标拟合、骨骼轨道插帧，以及基于已有生图工作流的姿态参考入口。每一步都保留可恢复的工程数据和验证记录；未执行的模型推理不作为通过项。

## 01 · 范围与设计决定

- 延续第二版的天蓝色工作台、Spine 4.2 JSON/atlas/PNG 导出、透明部件、拆层导入和本机 ComfyUI 作业恢复。
- 目标产物是可继续调整的骨骼、网格和动作。姿态图片是观察和留档材料，不能直接替代骨骼轨道。
- V3 把一个动作对应为一个“姿态研究”。研究中可以保存时间轴姿态、上传姿态图、调用现有生图连接生成姿态参考，再由用户对照图片编辑 R/B/X/Y 目标。
- 插帧输出的是 Spine 可编辑骨骼关键帧，不是渲染后的像素视频。像素补帧模型和图像姿态识别另列为后续研究。

## 02 · 数据模型与持久化

`src/lib/spine.ts` 新增可选的 `SpineProject.motionStudies`，保持第一、二版工程向后兼容。

- `SpineMotionStudy` 记录目标动作、FPS（12/24/30）、线性或阶梯曲线、创建/更新时间和最多 64 个姿态帧。
- `SpinePoseFrame` 记录稳定 ID、名称、动作时间、来源（`capture`、`upload`、`generated`、`reference`）、可选的 PNG data URL、尺寸和每个部件的 R/B/X/Y 目标。
- `fitStatus` 有 `ready`、`review`、`applied` 三态；缺失部件会记录 `fitError` 和补齐说明，便于用户复核。
- 工程校验拒绝未知部件目标、越界旋转/位移、重复帧 ID、非法图片 MIME 或尺寸，并限制研究数量、姿态图总量和工程总大小。
- 工程仍通过既有 IndexedDB 存储；刷新、切换创作页签和重新打开应用都会保留姿态图片及目标数据，不写入 localStorage。

## 03 · 姿态来源与人机协作

- “记录时间轴姿态”从当前动作采样全部部件，时间取主时间轴当前位置。
- “导入姿态图”读取 PNG/JPEG/WebP，标准化成可持久化的图片数据并显示在姿态卡片中；读取失败会在面板内显示错误。
- “生图关键姿态”复用 `generateMedia`。提示词要求完整角色、清晰动作姿态和保持角色身份；已有角色参考图会继续作为 `referenceAttachmentIds` 传给生图工作流。没有配置模型时按钮禁用。
- 姿态图不会自动反求关节、骨长、网格或权重。用户在姿态卡片中选择部件，手动编辑旋转（R）、弯曲（B）、X/Y 位移，再点“拟合”确认。
- 拟合只使用固定的当前动作和已提供目标：缺失部件从该时间的现有骨骼采样补齐，并将值限制在 Spine 工程允许的范围内。完整目标标记为 `applied`，部分目标标记为 `review`。

## 04 · 确定性插帧算法

实现位于 `src/lib/spineMotion.ts`，不依赖 GPU 或外部推理服务。

1. 将姿态按动作时长裁剪并按时间排序；约 0.5ms 内的重复时间只保留最后一帧。
2. 必须存在至少两个不同时间的姿态，单帧或同一时间的重复帧会明确拒绝。
3. 先对每一帧执行目标拟合，再按 12、24 或 30 FPS 生成采样时间，同时保留用户输入的姿态时间点。
4. 旋转和弯曲使用最短角度差，X/Y 使用线性混合；阶梯模式在下一姿态到达前保持左侧目标。
5. 每个部件输出独立的 Spine key track，并沿用 `linear`/`stepped` 曲线标记。单轨道受 300 个关键帧上限保护。

“插帧为新动作”保留源动作并生成名称带 `fitted` 的新 clip；“覆盖当前动作”只替换当前 clip 的轨道，研究和图片仍保留。新动作受工程 16 个 clip 上限保护。

## 05 · 工作台改动

- `src/components/SpineMotionStudyPanel.tsx` 提供 V3 模态面板：FPS、曲线、时间轴采样、姿态图预览、部件目标编辑、单帧拟合、删除姿态、新动作和覆盖动作。
- 只有存在两个不同时间点时，插帧按钮才可用；生成失败或图片读取失败不会吞掉错误。
- `src/components/SpineStudio.tsx` 在当前动作上懒创建姿态研究，停止播放后编辑，成功应用后回到动作时间轴；动作数量达到 16 时拒绝创建新 clip。
- 预览仍使用现有骨骼/网格渲染器，因此应用后的轨道与导出 JSON 使用同一套姿态采样逻辑。
- 天蓝色视觉保持第二版的局部 Spine 主题，不改写写作工作台或全局主题。

## 07 · 能力边界与下一步

当前版本没有集成或验证 OpenPose、MediaPipe、RIFE、ToonCrafter 等姿态识别/视频插帧模型，也没有从像素自动推断骨骼、IK、固定骨长或逐顶点 deform。没有真实生图服务、ComfyUI GPU 推理、原生 Tauri 窗口或 Spine 编辑器导入/另存回环的验收记录。

后续实现应先固定角色骨骼和部件，再将多张一致性姿态图转成带置信度的观测关键点，使用固定骨长/IK 生成 `SpinePoseTarget`，保留人工覆盖入口；像素插帧结果应先经过姿态拟合，再写入可编辑骨骼轨道。真实模型验收需要单独记录耗时、峰值显存、遮挡补全、透明边缘、身份一致性和 Spine 编辑器回环结果。

# 桌面应用截图校准（2026-11-06）

新建账号默认选择钉钉桌面接入。进入桌面设置后，也可以选择「其他桌面应用」，按可见窗口和所属进程绑定。桌面通道的内部平台 ID 仍为 `dingtalk_desktop`，以兼容已有账号、路由和历史数据。

## 使用流程

1. 选择应用，检测并选择目标窗口。钉钉只列出已核验的钉钉进程；其他应用列出可见的主窗口。
2. 点击「自动截图」，或者上传 PNG、JPEG、WebP 截图。上传整屏图片时先框出完整应用窗口，包含窗口边缘；也可以确认图片已经是完整窗口。
3. 拖动框选六个区域：消息栏/红点入口、会话列表、标题、聊天正文、输入栏、发送按钮。可放大截图、清除单个框或输入 0–1 相对坐标。输入栏应框住文字编辑区域，排除表情／附件工具栏和发送按钮，并清空草稿；正文应包含左右两侧气泡，红点入口应排除其他通知入口。
4. 点击「检查实时识别」。核对消息入口定位说明、会话栏识别文字、标题、未读红点、正文方向与草稿状态，保存账号。「执行方式」直接显示在应用选择下方，修改后保存并重新连接。
5. 在聊天路由登记人名或群名，并绑定机器人。标题包含名称即匹配，无需附带部门、群人数或状态。群聊仅 @ 模式需填写自己的显示名，也可为单个群选择全部新文本。

截图只用于本地校准，不作为模型输入。保存账号时，截图图片、窗口身份、截图尺寸及全部相对区域坐标一并保存到本机；重新编辑或重启应用后会恢复图片和框选。旧版未保存的截图无法补回，需要重新获取一次，尺寸相同会保留已有框选。窗口移动无需重新校准；改变窗口大小、侧栏宽度或内部布局后，需要重新截图框选。上传图片的尺寸与当前窗口必须一致，不会把桌面坐标当成窗口坐标使用。

已有桌面连接时，平台账号页直接编辑原账号，包括已断开的连接；多个联系人在「聊天路由」中添加，不重复创建桌面账号。添加其他平台可使用「添加其他平台账号」。

## 运行行为

- 配置版本 2 使用手动区域，不覆盖用户保存的坐标。旧版配置仍可读取，重新截图校准后升级；不自动修改已保存账号。
- 消息入口应只框单个按钮。钉钉旧配置如果框住整列菜单，仅在框内识别到唯一「消息」标签时缩小本次点击目标与红点检测范围；无法确认时显示重新框选提示，不点击整列中心。DING、审批等相邻入口的红点不触发消息入口。其他应用支持手动框选的单个按钮；与会话栏重叠的红点列只观察、不点击。
- 已有绑定会话出现在列表或当前标题时，直接检查会话，不反复点击入口。消息入口有红点而列表未出现绑定会话时，尝试进入后再识别；未确认成功的入口点击停止重复执行，直到识别到绑定会话或重新连接。优先进入可见、已登记、可唯一匹配的未读会话；无可处理红点时，每隔至少 15 秒轮询一个可见绑定会话，首轮建立历史基线，不将已有消息当成新消息回复。切换失败的会话冷却 15 秒后才能重试。
- 点击后保留未读状态，等待两次相同正文观察，避免红点清除或局部渲染丢失消息。没有红点时仍观察当前已绑定会话，接收窗口已经打开时的新消息。切换会话不检查输入栏草稿，也不改动草稿；进入目标会话后，实际写入回复之前再检查输入栏。
- 首次进入未读会话或历史视口失去重叠时，仅处理最新一条可读的收到消息；已有连续基线时处理可核验的新增消息。未读数字不被当作可靠的历史消息数量。重启保留去重历史；不会批量回复旧消息。
- 包含匹配优先最长名称。按 OCR 文字高度与行间距区分会话名称和紧邻的消息预览，避免预览提及联系人导致错误的同名判断。暂停的更长名称仍排除较短名称，真实同名行或等长规则歧义仍暂停处理。OCR 无法区分同名用户，请使用能区分的名称并检查预览。
- 新建钉钉配置默认后台模式，通过窗口消息操作，不移动鼠标；部分钉钉版本收到消息后会自行激活窗口，不能保证所有版本均不抢焦点。其他应用的键鼠操作不阻塞读取；钉钉正在前台且最近 5 秒有人操作时，暂缓点击和发送。点击逐层定位同进程可见子窗口，文字定位到框选输入区对应的聊天子窗口，每个字符发送前重新核验目标；不再把新版列表和输入栏的操作发送给外层 DingChatWnd。
- 其他桌面应用默认前台兼容模式，切换和发送前等待键鼠空闲；钉钉也可手动选择此模式。已有账号保留已保存模式，可在应用选择下方的「执行方式」中切换并保存、重连。等待状态明确说明当前是前台模式还是后台模式。输入前检查草稿，发送前再次核对标题和文字，点击发送框中心。已有草稿不覆盖，发送结果不明不自动重发。
- 桌面控制器初始化后，待发回复独立于消息观察状态进行发送检查；当前没有未读红点或可读消息，不阻塞已有回复。输入前因人工操作或草稿暂缓时，至少等待 5 秒后重新检查，保留同一条回复，不重复调用模型。后台点击使钉钉自行激活时，区分之前在其他应用的输入和激活后的新人工输入。
- 收到发送请求即报告“发送请求已收到”，并在当前截图或 OCR 调用结束后的检查点让出观察流程，优先进入目标会话；桌面输入仍串行执行。已点击清除的未读红点在让出时保留读取意图，避免丢失新消息。无法中断的单次原生调用仍受宿主发送超时限制。
- 收发记录显示暂缓原因与定位会话、检查草稿、写入、发送确认等进度。发送阶段连续 45 秒没有新进度或一次尝试总计达到 120 秒时，停止控制器，将尚未确认的发送转为待确认，禁止自动重发；后续可在聊天软件核对后标记。

## 适用范围与限制

适用于 Windows 上具有可截图窗口、可见红点、名称和文字聊天气泡的应用。正文仍采用本地 OCR 和气泡形状识别，支持范围取决于应用绘制和输入实现；这不保证任何桌面软件都可接入。图片、语音、附件、复杂富文本及屏幕外会话不自动理解或发现。输入栏在框选范围内找到唯一且中心位置相符的编辑控件时，检查完整控件画面，排除外围工具栏并避免过小框选漏掉草稿；找不到时继续检查原框选区域。保存的截图和坐标不会被改写。空输入框的提示文字可配置，有提示时需要可读的空 UIA 值辅助核验。没有可核验焦点或草稿的应用会停止输入。

本地发出气泡是发送核验依据，不代表服务器或对方已收到。运行需窗口未最小化、Windows 解锁。每次仅保存一个桌面控制器账号，防止同时争用输入。

## 不抢焦点方案实测（2026-11-06，未迁移）

在本机钉钉 9.0.4.261021001 上，以本账号会话为导航起点，只尝试打开用户授权的测试联系人 222，没有发送新测试消息。使用临时输入窗口作为前台，记录 `EVENT_SYSTEM_FOREGROUND` 事件并每 5 ms 采样前台窗口；同时核对目标聊天标题，不能将列表高亮或鼠标未移动视为通过。窗口消息及窗口样式方案另用独立进程的前台窗口复核。

| 方案 | 实际打开目标聊天 | 操作期间保持前台 |
| --- | --- | --- |
| 当前同步子窗口点击 | 是 | 否 |
| UIA `SelectionItem.Select` / `Invoke` | 否 | 否 |
| MSAA `Select(SELFLAG_TAKESELECTION)` | 否，仅列表选中 | 是 |
| MSAA 选中后向列表发送 Enter / 鼠标释放 | 否 | 是 |
| MSAA `DoDefaultAction` | 是 | 否 |
| `PostMessage` 异步点击 | 是 | 否 |
| 临时 `WS_EX_NOACTIVATE`，包括原生列表子窗口 | 是 | 否 |
| 局部焦点通知后异步点击 | 是 | 否 |

异步点击按 AutoHotkey v2.0.19 `ControlClick` 的 NA 分支发送相同的鼠标按下/释放消息，不调用 `AttachThreadInput` 或 `SetActiveWindow`；此项是消息机制对照，没有安装或执行 AutoHotkey。来源：<https://github.com/AutoHotkey/AutoHotkey/blob/v2.0.19/source/lib/win.cpp>。

没有方案同时满足“打开正确聊天”和“全程保持其他应用前台”，因此不接入生产驱动，也不将失败后抢回焦点作为后台成功。临时窗口样式均已恢复，辅助窗口与测试进程均已退出。实验脚本和事件记录仅保存在本地忽略目录 `artifacts/desktop-calibration-review/222-live/`；本轮只增加验证记录，保留之前尚未提交的功能修复。
